The fact that this particular collection is complete is not exposed.

RUBRIC aspect: the question asks which materials to use and which events start after a date. It does not ask about Community recommendation or the collection. The "officially recommended = in the Community collection" framing comes from the use case. The agent read the `EventFor`/`MaterialFor` schema (step 9) but had no prompt to join them. One could call this NOT_QUERIED, but the join is not the obvious next step from the question's wording.

## 3. Fixes

1. **Denormalise group collection membership onto the node rows.** Add `Event.collections` and `TrainingMaterial.collections` (collection names), or `elixir_groups`, populated from the same TeSS assignments as `EventFor`/`MaterialFor`. Every event or material query then shows membership, as `Tool.elixir_communities` already does for tools.
2. **Record completeness per collection.** On the edge or on a small `TessCollection` table, store `members_known = facet_count` and `complete = true`. The description can then say: "for collections marked complete, a missing edge means not in the collection". This replaces the blanket caveat.
3. **`/api/record` should include the record's edges,** or at least the group links (EventFor, MaterialFor, ToolFor with basis). The `/api/initiative` events and materials lists should include `basis` and `collection`.
