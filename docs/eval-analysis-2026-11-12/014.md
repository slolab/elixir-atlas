## E-PAN and HARVEST not classified as ended (component 1)

**HARVEST: DATA_WRONG.**
- `Initiative.status` for `initiative:harvest` = `current`, with end `2026-06`.
- The value comes from a model extraction on the HARVEST page. `data/extracted/initiative_statements.jsonl` has status `current`, with the evidence quote "The HARVEST project advances the FAIRification…", which is present tense, not a status label.
- The raw page shows no current/ongoing/status label (checked by regex on `how-we-work-scientific-programme-science-bfsp-harvest-ffb128ae4292.html`).
- The agent quoted it: "HARVEST lists an end in June 2026 but is labelled 'current' on the ELIXIR page", and left it unresolved.
- ASSUMPTIONS keep `planned` only for future starts, but no rule stops `current` after the end date.

**E-PAN: RETRIEVED_NOT_USED, but a representation choice made it hesitant.**
- `Initiative.end` = `2026-05`, taken from the main ELIXIR page as the build rule says.
- Review items for `start`, `end` and `nodes` record the ELIXIR-UK page's 2024-01-01 to 2027-01-01.
- The agent saw both (step 30) and declined to pick. The skill says to compare conflicting statements rather than rely on the merged value. Nothing tells the agent that the main page is the authoritative source for the period.

**Fix (shared with 012):**
- Add a derived `period_status` (ended / running / not_started as of the release date) with `period_basis` = "main ELIXIR page". Keep the page-stated status separate (`status_stated`) and never let a model-inferred present-tense "current" override a passed end date.
- Expose `end_basis: main_page` beside the conflict, so agents know which value the Atlas treats as canonical.

## Funding / in-kind for Commissioned Services (component 3)

**Class: NOT_QUERIED (answer completeness).**
- q5 (`009_q5_project_statements.json`) fetched `SourceStatement.funding` for all 2024-28 services. Every value is null or project-level, such as "This work was supported by ELIXIR … as Commissioned Service 2024-TECH-…" or "projects funded in 2025".
- No value is per Node. The only in-kind statement is FAIRferm's "TFTAK provides in-kind contributions", which concerns Estonia.
- The agent printed only the EU-project rows of q5 (steps 19–20 filter on excelerate, converge and steers). q7, the "in-kind" search, was restricted to EU-project names. The service side was never examined, and the absence never stated.

**Fix (data layer):** make the absence explicit.
- Add a `funding` field to `TakesPartIn` (Node → initiative), defaulting to `not_stated` with evidence when a source states it, like `HoldsRole.funding`.
- Or add a release-level coverage note: "per-Node funding or in-kind status of Commissioned Services: not published".

An explicit `not_stated` lets agents report the absence instead of skipping it.

**Fix:** a precomputed per-(Node, initiative) portfolio view (`/api/node` or a `NodePortfolio` table) with these columns:
- `on_elixir_main_page`
- `on_node_site` (+ URL)
- `elixir_period` / `node_site_period`
- `beneficiary_eu_contribution` (from `ParticipatesIn` via organisation country)
- `funding_stated`
- `conflicts` (review ids)

This one table answers 014 almost directly and most of 013.
