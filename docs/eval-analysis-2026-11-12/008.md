## 3. Fixes (data layer)

1. **Map project governance tables to the project.** HoNC / GA / board rows in a project handbook become `HoldsRole(person → project, work_item='Heads of Nodes Committee', role='member'|'deputy')`, not `InNode.role` and not `TakesPartIn → initiative:hons-committee`. This restores Kairi Koort's and Hedi Peterson's STEERS governance roles (and the same for every other Node's HoN/deputy in STEERS and CONVERGE).
2. **Turn report participant lists into plan-item edges.** When a milestone or deliverable report lists people ("Members of Tasks 3.3 and 3.4", "Project participants & others"), add `WorksOnPlanItem(person → that milestone)` and set `HoldsRole.work_item` to the milestone code. Also derive `WorksOnPlanItem(role='author')` from `Authored → Output → Delivers → PlanItem`. Heleri Inno then appears on M3.4 through the same path the agent used.
3. **Precomputed "Node people on initiative" view.** One row per (Node, initiative, person, role/work item, source) built from HoldsRole ∪ WorksOnPlanItem ∪ governance roles. Expose it as `/api/node?id=…&initiative=…` or a `NodePersonRole` table. The question is literally this join, and the 849 KB initiative view is not a usable path.
4. Add the per-initiative `not_public` statement (007 fix 2) so time and funding limits are stated, not inferred.
